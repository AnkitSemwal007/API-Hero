# API Hero 2.12.1 — Release notes

**Date:** 2026-08-14  
**Extension:** `ankitsemwal.api-hero` **2.12.1**  
**npm CLI package:** `@ankitsemwal007/api-hero` **2.12.1** (binary `apihero`)

## Summary

**2.12.1** adds first-class GraphQL and WebSocket Request Editor UX, Environment & Variables UI, centralized Authentication UI, and Collection Run Setup. CLI and MCP reuse the same runtime. Backward compatible with **2.12.0**.

## Request & Protocol UX

The Request Editor protocol selector writes `@protocol` (`http` omits the directive):

- **GraphQL** — Query, Variables, and optional Operation name as a projection of the existing JSON envelope. Run still uses `ExecutionOrchestrator`. HTTP 200 with GraphQL `errors` is not a successful GraphQL operation and shows a **GraphQL Errors** card (messages are already secret-masked). Subscriptions are not included.
- **WebSocket** — **Run Session** is the same bounded session as CLI: connect → optional send of the Message body → receive one text frame → close. The socket is not kept open after the run. Persistent connections, subscriptions, reconnect, and streaming are not included.

See [GraphQL](../user/graphql.md) and [WebSocket](../user/websocket.md).

## Environment & Authentication

- **Environment & Variables UI** — Manage Environments for named environments and Workspace / Global scopes. The Request Editor Variables tab edits document variables and shows a masked resolution preview. Collection Run Setup previews resolved variables for the selected environment.
- **Centralized Authentication UI** — Shared secret-free Auth UI on Request Editor, Collection Auth, and Collection Run Setup.

Supported types:

- No Auth
- Bearer Token
- Basic Auth
- API Key

OAuth is not included.

See [Environments](../user/environments.md), [Variables](../user/variables.md), and [Authentication](../user/authentication.md).

## Collection Run Setup

**API Hero: Run Collection**, **Run Folder**, and **Run Selected Requests** open a dedicated **Collection Run Setup** screen:

- Environment selection (including No Environment)
- Variable preview (sensitive values masked)
- Authentication configuration
- Request selection
- Continue on Error / Stop on First Failure

**Run Again** on the Collection Run Report reopens Setup with the previous submitted configuration.

Retry and skip-destructive remain workspace settings (not Setup fields). `ask` and `skip-invalid-requests` remain available to MCP/settings.

See [Collection Runner](../user/collection-runner.md).

## Reports

- GraphQL error presentation in the Response Viewer and Collection Run Report
- WebSocket session and message presentation (bounded session recap)
- Existing Collection Run Report JSON and standalone HTML exports are unchanged (redacted snapshots)

## Security

- Secret masking and redaction across GraphQL error messages, WebSocket close reasons, Authentication UI, variable preview, and reports
- WebSocket close-reason redaction
- Secrets are not added to History

## CLI / MCP

The `apihero` CLI and MCP reuse the same `@protocol`, authentication, and variables runtime. There is no separate GraphQL, WebSocket, Authentication, or Variables CLI. Protocol is chosen on the request. There is no `--graphql`, `--websocket`, `--ws`, `--listen`, or `--stream` flag.

## Not included

- OAuth
- Persistent WebSocket connections
- Scenarios as a current VS Code product capability
