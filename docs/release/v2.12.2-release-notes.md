# API Hero 2.12.2 — Release notes

**Date:** 2026-08-14  
**Extension:** `ankitsemwal.api-hero` **2.12.2**  
**npm CLI package:** `@ankitsemwal007/api-hero` **2.12.2** (binary `apihero`)

## Summary

**2.12.2** polishes WebSocket New Request and Request Editor UX, imports Postman GraphQL bodies as native `@protocol graphql`, and adds Source Quick Run from a JS/TS `fetch("https://...")`. CLI and MCP reuse the same runtime. Backward compatible with **2.12.1**.

## What's new

### WebSocket improvements

The Request Editor toolbar for WebSocket is **Protocol | WS | URL**. There is no HTTP method selector. Method stays `GET` internally on the `.api` request line for compatibility.

- New Request and the Request Editor hide the HTTP method field for WebSocket.
- WebSocket URL defaults to `ws://localhost:8080/socket` (not the REST `https://httpbin.org/get` default).
- The Body tab is **Message**. WebSocket messages do not receive REST Content-Type defaults.
- Request bodies that start with an alphabetic word (WebSocket plaintext, GraphQL `query` / `mutation`, HTTP text) are no longer reported as unknown HTTP methods. WebSocket messages are never treated as an HTTP method. The lexer still detects real unknown request methods such as `FETCH /unknown`. A body line that is a known HTTP method followed by a URL-like remainder can still start a new request.

WebSocket remains a **bounded session**: connect → optional send → receive one text frame → close. It is **not** a persistent WebSocket client. Persistent connections, subscriptions, reconnect, and streaming are not included.

See [WebSocket](../user/websocket.md).

### Postman GraphQL import

Collection `body.mode = graphql` maps to native `@protocol graphql` (query, variables, operation name). Headers, auth, and variables are preserved. The existing GraphQL envelope and `ExecutionOrchestrator` path are reused.

Successful Postman GraphQL imports are native GraphQL requests, not unsupported/raw JSON stubs. Insomnia GraphQL import remains a stub.

See [GraphQL](../user/graphql.md) and [OpenAPI / Postman / Insomnia import](../user/openapi-import.md).

### Source Quick Run

Right-click a JS/TS `fetch("https://...")` and **Run Request** without `@api-hero`. Unique catalog matches reuse the existing `.api` file; otherwise a temporary request runs through `ExecutionOrchestrator`. Temporary runs are not opened as untitled editors.

```text
source API call
↓
Run Request
↓
detect request
↓
reuse existing API request OR synthesize temporary request
↓
ExecutionOrchestrator
```

`@api-hero` remains the explicit persistent mapping for CodeLens, Open API Definition, and Generate TypeScript. Ambiguous catalog matches fall back safely (QuickPick, or a temporary request if you cancel). Unique or picked catalog matches that cannot be opened show a specific error and do not synthesize a temporary request. Mapped `@api-hero` open failures show a specific error. GraphQL and WebSocket catalog entries are not Quick Run matches.

See [Source-code integration](../user/source-integration.md).

## Compatibility

Backward compatible with **2.12.1**. Existing `.api` files and the bounded WebSocket execution pipeline are unchanged.

## Known limitations

- WebSocket remains a bounded session — not a persistent client
- OAuth is not included
- GraphQL subscriptions are not included
- GraphQL schema explorer / schema import is not included
- Scenarios are not a current VS Code product capability
- Insomnia GraphQL import remains a stub
