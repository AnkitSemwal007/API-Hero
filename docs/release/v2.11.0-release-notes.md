# API Hero 2.11.0 — Release notes

**Date:** 2026-08-13  
**Extension:** `ankitsemwal.api-hero` **2.11.0**  
**npm CLI package:** `@ankitsemwal007/api-hero` **2.11.0** (binary `apihero`)

## Summary

**2.11.0** adds GraphQL-over-HTTP and bounded WebSocket sessions to the same execution pipeline as REST. VS Code, the `apihero` CLI, and MCP share one runtime. Dual Marketplace / npm README packaging from **2.10.1** is included.

## GraphQL Phase 1

`@protocol graphql` runs **queries and mutations over HTTP** through `NodeHttpTransport`.

- JSON body may include `query`, `variables`, and `operationName`
- Existing `{{variable}}` substitution, headers, and authentication profiles apply
- Collections, scenarios, assertions, and extraction reuse the existing engines
- CLI (`apihero run request` / `collection` / `scenario`) and MCP use the shared orchestrator
- HTTP transport success is not GraphQL success: HTTP 200 with `errors` (including partial `data` + `errors`) is not a successful GraphQL operation
- GraphQL `errors[].message` values use existing secret masking
- Collection retry for GraphQL HTTP `408` / `429` / `502` / `503` / `504` matches REST; HTTP 200 with GraphQL `errors` is not retried

Not included: subscriptions, GraphQL-over-WebSocket, GraphQL schema import, gRPC.

## WebSocket Phase 1

`@protocol websocket` runs a **bounded** session: connect → optional text send → receive one text frame → close.

- URLs are `ws://` or `wss://`
- The request body is the optional UTF-8 text frame to send (prefer JSON)
- The first text frame is the response body; JSON reuses existing `expect` and `@extract`
- Variables, authentication headers, collections, and scenarios use the existing pipeline
- `@timeout` bounds the whole session; cancellation closes the socket
- Connect / DNS / timeout remain collection-retry eligible; send / receive failures do not retry a half-open session
- The socket is closed on every path, including timeout, cancellation, and assertion failure
- Presentation reports `WebSocket received` — not a fake HTTP `200` or status `0`
- VS Code, CLI, and MCP share the same executor and transport

Not included: persistent connections, subscriptions, reconnect, infinite streaming, connection pooling, a WebSocket server, binary frames, gRPC.

## CLI and MCP

Install the CLI with:

```bash
npm install -g @ankitsemwal007/api-hero
apihero --version
```

GraphQL and WebSocket requests use the same commands as HTTP:

```bash
apihero run request <request>
apihero run collection <collection>
apihero run scenario <scenario>
```

There is no `--graphql`, `--websocket`, `--ws`, `--listen`, or `--stream` flag. Protocol is `@protocol` on the `.api` file.
