# API Hero 2.8.4 — Release notes

**Date:** 2026-08-12  
**Extension:** `ankitsemwal.api-hero` **2.8.4**

## Summary

**2.8.4** polishes everyday VS Code workflows on the same execution core:

1. **Collection Execution Controls** — Run Options for retries and optional DELETE skip; attempt progress in Execution / Run Report
2. **OpenAPI environment safety** — preserve the active environment on import; keep imported envs selectable; warn on undefined security schemes without inventing auth
3. **Collection Run Report UX** — compact summary/rows, filters, folder grouping, and drill-down Details
4. **Variable Trace UX** — compact Variables status; expand for full trace / unresolved
5. **Scenario menu cleanup** — Create Scenario removed from Collections top-level `…`; dedicated Scenario UX unchanged
6. **Security masking** — Response UI aligns with MCP/cURL for API-key / auth-token headers; OpenAPI server variables marked sensitive by name

## Highlights

- Collection runs can retry transport / `408`/`429`/`5xx` (settings or per-run QuickPick); intermediate attempts do not write extracts — only the final attempt does; Attempts list shows progress vs the authoritative final outcome
- DummyJSON (or any active env) stays selected when importing another OpenAPI spec (e.g. OpenAI)
- Run Reports stay scannable on large collections; Details still hold Response, Assertions, Variables, and diagnostics
- Sensitive headers (`Authorization`, `Cookie`, `x-api-key`, `x-auth-token`, …) masked consistently in the Response panel
- Nine MCP tools remain available (including `apihero_run_scenario`); Copy as cURL continues to work
- Public headless CLI / CI distribution is **not** part of this release (implementation retained in-repo only)
